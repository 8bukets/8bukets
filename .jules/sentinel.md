## 2026-01-05 - [CSV Injection Vulnerability]
**Vulnerability:** Scraped user input (titles, authors) was written directly to CSV files without sanitization. If these fields started with characters like `=`, `+`, `-`, or `@`, they could be interpreted as formulas by spreadsheet software (Excel, LibreOffice) when opened by a user. This allows arbitrary code execution or data exfiltration via the spreadsheet application.
**Learning:** Even if the scraper itself doesn't execute the code, the *output* file becomes a vector for attack. "Data at rest" in a CSV can be "active" when opened in the wrong tool. We must treat all external input as potentially malicious, even for simple text formats like CSV.
**Prevention:** Implemented `sanitize_for_csv` method that prepends a single quote `'` to any field starting with formula triggers (`=`, `+`, `-`, `@`). This forces spreadsheet software to treat the cell as text. Applied this sanitization to all dynamic fields in the CSV output.
