## 2024-01-30 - [CSV Injection Vulnerability in Scraper Output]
**Vulnerability:** The scraper was writing user-controlled data (titles, authors, categories) directly to a CSV file without sanitization. If any of these fields started with characters like `=`, `+`, `-`, or `@`, they could be interpreted as formulas by spreadsheet software (Excel, LibreOffice, Google Sheets), leading to potential command execution or data exfiltration when a user opens the CSV.
**Learning:** CSV files are not just plain text; they are often opened in applications that support active content. Simple text writing is insufficient for security when the input is untrusted. We must assume all scraped content is untrusted.
**Prevention:** All fields written to CSVs that might contain untrusted input must be checked. If a field starts with a dangerous character (`=`, `+`, `-`, `@`), it should be escaped by prepending a single quote `'` (e.g., `'=SUM(1+1)`), which forces the spreadsheet application to treat it as a string literal.
