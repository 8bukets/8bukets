## 2024-05-23 - BeautifulSoup Parsing Optimizations
**Learning:** `SoupStrainer` with `class_` argument (e.g., `SoupStrainer('article', class_='post')`) yielded 0 results with `html.parser`, while `SoupStrainer('article')` worked correctly. Additionally, standard `re.sub` for whitespace normalization is significantly slower (5x) than `' '.join(text.split())` for simple cases. `ThreadPoolExecutor` with CPU-bound `BeautifulSoup` parsing (using `html.parser`) degrades performance due to GIL contention and overhead compared to sequential processing in a single process.
**Action:** Use `SoupStrainer` with simple tag names to reduce memory and parsing overhead (9% gain). Use `split/join` for whitespace cleaning (80% gain for that function). Avoid offloading CPU-bound tasks to threads if they hold GIL.
