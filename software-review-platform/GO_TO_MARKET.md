# Go-To-Market Plan

## Goal

Launch `software-review-platform` in a way that uses the current `software-online-review.com` asset as a traffic bridge instead of replacing it outright.

## Positioning

The product should be positioned as a trust-first software review platform.

Core message:

- better software decisions through more credible reviews
- transparent moderation
- structured software discovery

## Launch Model

Recommended model:

- keep the current live site active
- launch the app on `app.software-online-review.com`
- use the live site to direct qualified traffic into the app

## Phase 1: Soft Launch

Goal: validate the app with controlled exposure before broad promotion.

### Actions

- deploy the app to the subdomain
- add a homepage CTA on the current site
- add a “Write a review” CTA
- add a “Browse software reviews” CTA
- create one short landing page explaining the new platform

### Success Signal

- real visitors reach the app
- users can browse and submit reviews
- no major onboarding confusion appears

## Phase 2: Seed Discovery

Goal: give the new app a small but meaningful traffic base.

### Sources

- internal links from existing content
- homepage modules on the current site
- category pages that introduce review topics
- direct links to initial software pages

### Tactics

- link relevant old posts to matching software profiles
- add featured software blocks on existing content pages
- publish a “new review platform” explainer page

## Phase 3: Trust Messaging

Goal: clearly differentiate the product from generic directories.

Key messages:

- moderated reviews
- more useful buyer context
- better trust signals over time
- software discovery with structure, not noise

Use these in:

- homepage copy
- landing pages
- CTA sections
- onboarding text

## Phase 4: Early User Acquisition

Goal: get the first real contributors and readers.

### Initial User Targets

- readers already visiting `software-online-review.com`
- software-curious users from existing SEO content
- founders, marketers, and developers in categories already covered by the site

### Practical Tactics

- invite a small number of known reviewers or contacts
- manually collect first review contributions
- promote a few high-value software profiles rather than the whole app

## Phase 5: Early Vendor Angle

Goal: prepare the future monetization story without overbuilding too early.

Initial vendor narrative:

- better software presence
- better trust through quality reviews
- future claimable product pages
- future premium visibility and vendor tooling

Do not over-sell this in MVP. Just leave the path open.

## Phase 6: Measure Early Fit

Watch for:

- visits to software detail pages
- review submissions
- moderation volume
- comment activity
- repeat visits to seeded software pages

The first goal is not scale. It is clarity and signal quality.

## Suggested Homepage CTA Copy

Examples:

- Browse software reviews
- Explore trusted software insights
- Write a review
- Discover tools with more credible feedback

## Suggested Landing Narrative

Short version:

Software Review Platform helps people discover better software through structured reviews, moderation, and clearer trust signals.

## What To Avoid

- launching with empty pages
- trying to promote too many categories at once
- replacing the live site immediately
- positioning the product as “just another directory”
- adding monetization language too early in the user journey

## First 30-Day Focus

1. make the app stable
2. route traffic from the current site
3. seed quality software pages
4. gather the first real reviews
5. refine trust and moderation messaging

## Long-Term GTM Direction

After soft launch, the strongest growth levers are likely:

- content-to-app conversion
- category landing pages
- structured software pages
- review-driven trust signals
- future vendor claim and premium listing flows
