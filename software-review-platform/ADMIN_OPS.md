# Admin Operations

## Goal

Define the day-to-day workflow for running the platform once reviews and users start flowing through the system.

## Core Admin Responsibilities

Admins are responsible for:

- reviewing pending submissions
- approving or rejecting reviews
- maintaining review quality
- watching for spam or abuse
- keeping software pages useful and credible

## Daily Workflow

## 1. Review the Moderation Queue

Start each session by checking pending reviews.

For each pending review:

- confirm it is relevant to the software listed
- confirm it is readable and specific
- confirm it is not obvious spam
- confirm it is not abusive or misleading

## 2. Decide: Approve or Reject

Approve when the review:

- is relevant
- has useful substance
- reflects a believable use case
- adds value to the software page

Reject when the review:

- is spam-like
- is abusive
- is obviously fake or low-value
- is unrelated to the product
- exists only to manipulate ratings or visibility

## 3. Handle Comments and Ratings

Watch for:

- comment spam
- low-value repetitive comments
- rating abuse
- coordinated or suspicious activity patterns

Comments should improve context, not add noise.

## 4. Monitor Software Page Quality

Check whether software pages:

- have enough content to feel real
- show a useful description
- have at least one credible review where expected
- avoid empty or broken sections

## Moderation Principles

- favor clarity over speed
- protect trust over volume
- approve useful mixed or critical reviews, not just positive ones
- avoid over-polishing real user language into marketing copy
- keep the platform feeling human and credible

## Review Decision Rules

### Approve

Approve when the review is:

- specific
- relevant
- understandable
- not obviously manipulative

### Reject

Reject when the review is:

- generic filler
- copied or repetitive
- clearly promotional
- clearly hostile without substance
- unrelated to actual product use

### Escalate

Escalate internally if:

- the review may contain legal risk
- the content looks coordinated or abusive
- the same user pattern appears across multiple pages
- the review appears tied to impersonation or fraud

## Admin Quality Checklist

Before approving a review, ask:

- does this sound like a real software experience
- would this help a buyer
- does this improve the page rather than dilute it
- is the rating consistent with the text

## Early Admin Cadence

For the first launch period:

- check moderation daily
- review new software page quality every few days
- monitor whether seeded content still feels balanced
- fix empty states and clarity issues quickly

## First Metrics To Watch

- pending review count
- approval rate
- rejection rate
- comment volume
- suspicious submission patterns
- software pages with no useful content

## Tooling Priorities

As the platform grows, admins should gain:

- clearer moderation queue filters
- rejection reason templates
- suspicious activity markers
- content quality flags
- basic moderation analytics

## Working Standard

The platform should feel curated and trustworthy, not crowded and noisy.

That means admin decisions should optimize for long-term trust, not short-term content volume.
