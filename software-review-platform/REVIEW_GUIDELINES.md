# Review Guidelines

## Goal

Define what a good review looks like and how moderation should judge quality.

## What Good Reviews Should Do

A good review should help another person understand:

- what the software is useful for
- what it does well
- where it falls short
- who it is best suited for

## Good Review Characteristics

Good reviews are:

- specific
- readable
- relevant
- grounded in actual use
- balanced enough to feel credible

## Strong Review Elements

Useful reviews often include:

- real use case
- team size or context when relevant
- key strengths
- key weaknesses
- pricing or value perception
- learning curve or implementation difficulty

## Reviews To Avoid

Low-quality reviews include:

- generic praise with no detail
- generic criticism with no substance
- obvious marketing copy
- copied or repetitive wording
- hostile language without meaningful content
- content unrelated to the software

## Tone Standard

Reviews do not need to be polished, but they should be understandable.

They can be:

- positive
- mixed
- critical

All three are allowed if they are useful and credible.

## Moderation Policy Basics

Approve reviews that:

- are relevant to the product
- contain useful detail
- feel like a real user perspective
- contribute to trust and buyer understanding

Reject reviews that:

- are spam
- are fake-looking
- exist only to manipulate ratings
- are abusive or hateful
- have no meaningful informational value

## Rating Guidance

Ratings should broadly match the written review.

Warning signs:

- perfect score with shallow praise
- lowest score with no substance
- repeated patterns across many reviews

## Comment Guidance

Comments should:

- ask useful questions
- clarify specific points
- add practical perspective

Comments should not:

- repeat the same vague reaction
- promote unrelated links
- attack users
- create thread noise

## Early Platform Standard

In the first launch phase, the bar should be intentionally higher.

It is better to have fewer useful reviews than many weak ones.

## Example Of A Useful Review

Useful pattern:

- what the tool was used for
- what worked well
- what was frustrating
- whether the reviewer would recommend it and to whom

## Example Of A Weak Review

Weak pattern:

- “Great tool”
- “Bad experience”
- “Best platform ever”

Without supporting context, these do not help buyers.

## Long-Term Direction

Over time, review quality can be strengthened with:

- structured prompts
- verified reviewer flows
- moderation heuristics
- trust scoring

## Working Rule

If a review does not help a real buyer make a better decision, it probably should not be approved.
