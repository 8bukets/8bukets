# Seed Content Plan

## Goal

Seed the app with enough structured content that the first live version feels intentional instead of empty.

## First Content Principle

The goal is not volume. The goal is credibility.

The first release should contain a small number of software profiles with enough structure and moderation quality to demonstrate what the platform is supposed to become.

## Initial Target

Recommended first batch:

- 10 to 20 software profiles
- 1 to 3 reviews per high-priority profile
- a small number of approved comments
- a small number of ratings

This is enough to make category pages, software detail pages, and moderation flows feel real.

## Recommended First Categories

Choose categories that fit both the existing `software-online-review.com` content direction and real buyer intent.

Suggested starter categories:

- SEO and marketing tools
- analytics tools
- content and CMS platforms
- AI productivity tools
- developer tools
- business software with strong comparison intent

## Recommended Software Selection Rules

Pick software entries that satisfy at least one of these:

- already mentioned in existing site content
- relevant to current Project SOR themes
- easy to describe clearly in a structured profile
- likely to attract searchable buyer intent
- useful for future review comparisons

## Suggested Profile Structure

Each software record should have:

- name
- slug
- short description
- category
- clear use case
- homepage or canonical source link if needed
- review count
- aggregate rating when available

## Review Seeding Strategy

Do not seed fake-looking review volume.

Use a small, believable starting set:

- one balanced positive review
- one critical or mixed review where useful
- one concise practical review focused on actual use case

The tone should feel like a real software user, not marketing copy.

## Review Quality Rules

Seed reviews should:

- mention actual use cases
- include strengths and weaknesses
- avoid generic hype
- avoid exaggerated certainty
- be short enough to scan but specific enough to trust

## Comment Seeding Strategy

Only add comments if they improve realism.

Good starter comment types:

- clarification question
- agreement with a specific point
- note about a missing feature

Avoid:

- filler praise
- repetitive one-line reactions
- comment spam

## Rating Strategy

Use believable spread.

Avoid:

- perfect ratings everywhere
- uniform scoring across all products

Prefer:

- some strong scores
- some mixed scores
- visible variation between products

## Suggested First 10 Profile Types

Not a final list, but a good shape for the first batch:

1. one SEO platform
2. one web analytics platform
3. one CMS or website platform
4. one AI writing or research tool
5. one email marketing tool
6. one CRM or sales tool
7. one developer productivity tool
8. one hosting or deployment tool
9. one ecommerce enablement tool
10. one knowledge management tool

## Content Source Guidance

Use the existing site and workspace as inspiration, not as a direct dump.

Allowed source patterns:

- current content themes from the live site
- product categories already present in SOR content
- manually curated software entries

Avoid:

- bulk importing WordPress posts into software profiles
- turning every old article into a software record
- mixing editorial content with structured product data

## Approval Standard

Before launch, every seeded profile should pass this check:

- does it look like a real software page
- does it have a clear category
- does it have at least one useful review
- does it support trust rather than just filling space

## Launch Minimum

The app is ready for soft launch when it has:

- at least 10 strong software entries
- at least 5 to 10 approved reviews total
- visible category coverage
- no obviously empty or broken pages

## After Launch

Once the first batch is live:

- observe which software pages attract interest
- expand categories gradually
- improve high-traffic pages first
- add more reviews only where depth improves trust
