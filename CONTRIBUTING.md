# Contributing

Thank you for contributing! This project follows a trunk-based workflow.

How we work
- main is the protected, deployable branch.
- Create short-lived feature branches: feature/<short-description>
- Open a Pull Request targeting main when your change is ready for review.
- Add the "automerge" label to the PR if you want the bot to merge it automatically after required checks and reviews pass.

Pull request checklist
- [ ] Follow the PR template
- [ ] Add tests for new functionality or bug fixes
- [ ] Ensure CI passes
- [ ] Request at least one reviewer

Branch naming
- feature/<name>
- fix/<issue>
- hotfix/<issue>

Auto-merge
- To enable auto-merge after approvals and passing checks, add the "automerge" label to your PR. The auto-merge workflow will merge when the PR is mergeable.

Code style and tests
- Keep changes small and focused.
- Run tests locally before opening a PR.

Thanks for improving the project — your contributions matter!
